1. PRODUCT IDENTITY & MISSION
--------------------------------------------------------------------------------
ellmos-homebase-mcp is a unified, local-first Model Context Protocol (MCP) server
that equips local LLMs (Ollama, Qwen, Llama, and local harnesses) with a comprehensive
capability stack: persistent SQLite memory, knowledge digest with FTS5 search,
state and task tracking, credential-free model routing, swarm coordination patterns,
passive API discovery, local automation staging, and plugin exploration over stdio.

Key architectural highlights:
  1. 100% Local-First & Zero Cloud Egress: Zero external network calls required.
     All persistent memory, knowledge, and state are stored in a local SQLite
     database (~/.homebase/) using Write-Ahead Logging (WAL) and busy timeouts.
  2. Strict Engine Seams & Fail-Closed Discipline: Implements MODE-CONTRACT.md;
     seamlessly toggles between bundled zero-dependency SQLite storage and canonical
     external engines (Gardener, Rinnsal, USMC) without silent fallbacks.
  3. Canonical-Only Seams: hb_policy_*, hb_ticket_*, hb_lock_* modules provide
     read-only introspection into policy-registry, ticket-master, and lock-master,
     unconditionally failing closed if canonical engines are unreachable.
  4. Team-Memory & Agent Provenance: Built-in agent_id tracking across facts,
     knowledge entries, and tasks prevents cross-agent contamination in swarms.
  5. Credential-Free Discovery & Planning: Routing recommendations, swarm patterns,
     and API exploration function completely offline without API keys or tokens.
  6. Multilingual Schema Parity: Native tool and schema descriptions for en, de,
     es, zh, ja, ru with automated fallback to English.

  - Need: Comprehensive memory, knowledge search, and state persistence for
    local models (Ollama, Qwen, Llama) without cloud dependencies or subscriptions.
  - Value: Single stdio MCP server providing 51 tools, SQLite WAL storage,
    full offline operation, and seamless integration with local harnesses (BACH).

Persona 2: Multi-Agent Swarm Orchestrators & Autonomous Workflow Architects
  - Need: Reliable coordination, shared memory with clear attribution, task queues,
    and structured planning patterns for multi-agent collectives.
  - Value: Native agent_id provenance, swarm decomposition templates (boss/worker,
    parallel chunks, consensus voting), and isolated task state machines.

Persona 3: Enterprise Security & Data Governance Officers
  - Need: Verifiable zero-egress guarantees, fail-closed access policies,
    and non-elevation compliance for agent tools in restricted environments.
  - Value: Zero telemetry, fail-closed canonical engine seams (MODE-CONTRACT.md),
    RunAsInvoker unprivileged execution, and formal 48h Security Response SLA.

Persona 4: Cross-Framework AI Assistants & Pair Programmers
  - Need: Seamless tool interoperability across Claude Code, Claude Desktop,
    Codex, Antigravity, and Cursor.
  - Value: Standard stdio JSON-RPC transport, machine-readable discovery via
    llms.txt and server.json, and bilingual English/German documentation.

3. ARCHITECTURAL INVARIANTS & GOVERNANCE
--------------------------------------------------------------------------------
The project strictly enforces 10 runtime invariants (INV-LOCAL-01 to INV-SLA-10):
  - INV-LOCAL-01: 100% Local-First & Zero-Egress Storage (~/.homebase/ SQLite WAL)
  - INV-ENGINE-02: Strict Engine Seams & Fail-Closed (MODE-CONTRACT.md compliance)
  - INV-SEAM-03: Canonical-Only Seam Isolation (hb_policy_*, hb_ticket_*, hb_lock_*)
  - INV-PROV-04: Deterministic Provenance & Team-Memory (native agent_id attribution)
  - INV-CRED-05: Credential-Free Routing & API Discovery (offline exploration)
  - INV-STAGE-06: Plan-Only Staging & Bounded Offline Queues (hb_conn_*, hb_auto_*)
  - INV-I18N-07: Full Native Multilingual Schema Parity (en, de, es, zh, ja, ru)
  - INV-PERM-08: Non-Elevation & RunAsInvoker Principle (unprivileged execution)
  - INV-SYNC-09: Multi-Host Lock & Conflict Copy Discipline (fail-closed locks)
  - INV-SLA-10: 48h Security Response & 5-Day Triage SLA (formal response guarantees)
